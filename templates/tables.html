Tables and relationships

These are the nine tables from the proposal. The SQL that creates them is in schema.sql.

Primary keys

  • Student.student_id
  • Skill.skill_id
  • StudentSkill uses both student_id and skill_id together
  • Client.client_id
  • Project.project_id
  • Proposal.proposal_id
  • Contract.contract_id
  • Payment.payment_id
  • Review.review_id

Relationships

One-to-one here is a foreign key with UNIQUE, so the child id cannot be repeated. It is the one-to-many idea with a limit of one.

From To Type Where it is stored
Student Skill Many-to-many StudentSkill
Client Project One-to-many Project.client_id
Project Proposal One-to-many Proposal.project_id
Student Proposal One-to-many Proposal.student_id
Project Contract One-to-one Contract.project_id is unique
Proposal Contract One-to-one Contract.proposal_id is unique
Contract Payment One-to-many Payment.contract_id
Contract Review One-to-one Review.contract_id is unique

What happens on the site

  1. A client posts a project. The new row starts as open.
  2. A student submits one proposal for that project.
  3. Accepting a proposal writes four changes together: that proposal becomes accepted, the others become rejected, a contract is inserted, and the project becomes in progress.
  4. Payments are extra rows for the same contract.
  5. Saving a review marks the contract and the project completed. A second review is refused because contract_id is unique.
